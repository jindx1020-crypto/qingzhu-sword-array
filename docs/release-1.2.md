# 1.2 修复验收报告

验收日期：2026-10-08。游戏：青竹剑阵 · 虚天殿篇 1.2。原创代码许可：GPL-3.0-only。

**结论：本地技术验收通过。** 1.2 是修复版，处理 1.1 发布后整体审核发现的界面、存档待保存链、文案与构建验收工具问题。存档格式 1、存档键 `fanren-qingzhu-v1`、records schema 1 与全部规则版本号不变，旧存档无需转换。

### 存档

| 问题 | 1.2 处理 |
|---|---|
| 修持解锁用磁盘状态判断、扣费叠加在待保存记录上，写入失败期间同一节点点两次会扣两次心得 | 判断改读待保存链实际使用的基础记录（`baseSave()`）；已修持但尚待保存时提示重试 |
| 药园与出发补给用界面上的旧 garden 整份写回，覆盖待保存记录里刚结算的研究点与凭据，且该局已计入 history 无法再领 | 组件改为提交基于基础记录计算的更新函数，研究点是否足够也在基础记录上判断；键位改绑与返还预览同样读基础记录 |
| 采用导入／恢复记录、或在待处理恢复资料时开新历练，会静默放弃待保存结果；确认框未提及 | 确认框写明将放弃待保存结果并提供「导出本次待保存记录」；恢复资料开局说明新存档只沿用本页当前载入的长期进度 |
| 「保留原文并开启新历练」列出旧记录进度，实际新存档从当前载入的长期进度（可能为空白）开始 | 说明新存档沿用的心得与修持，旧记录需在设置中采用才能继续 |
| 结算页「重试保存」或其他写入顺带落盘结算后，仍显示「本次结算尚未保存成功」 | 每次成功写入后按存档凭据判断本局是否已结算 |
| 本页自己写入后，恢复候选或导入预览的快照过期，被误报为「另一窗口更新了存档」并停止写入 | 仅当磁盘主档正是本页刚写入的内容时，改判为「预览过期」：刷新预览并请玩家再次确认；任何其他变化仍按跨窗口冲突处理 |
| history 条目字段只校验 time／kills／path，特制导入可让成绩页整页报错，或让写入在 try 之前抛异常而无提示 | 成绩页与成就判断对非数值字段降级显示；成就计算移入写入的 try |

### 战斗、秘境与文案

- 危险区循环的敌方分支在命中使历练结束或节点完成后继续结算后续场地，可多算击杀、掉落或让留符在整备中引爆。1.2 在该分支阶段变化后立即停止，仅作用于秘境引擎；规则 1／2 旧引擎保持冻结行为。
- 无尽读档用 `倍率 ** 圈数` 而连续游玩逐圈连乘，两者末位不同，读档后的新敌人伤害与连续游玩分叉。1.2 读档同样逐圈连乘。
- 经济 4 有限补养只要恢复量大于 0 就可购买，差 0.03 生命也收 80 灵石并占一次额度。1.2 差不足 1 点生命或护盾视为已满；已保存的补养记录仍按原校验有效。
- 开启「普通伤害数字」后，持续火区把特效数组填满 180 上限，「主符爆发／聚锋／反击」等关键标签不再出现。1.2 普通数字在 120 停止，关键标签、暴击与首领数字保留余量。特效不进存档，不消费随机数。
- 连续事件结局「领取灵石」显示全额，实际在开局偏向休整时只发 80%；开局选项的即时回复未写明。1.2 文案与发放共用同一计算，并写明即时回复 8% 生命或 15 灵力。
- 无尽每圈末整备写「此行结束后结算研究点与修炼心得」「收拢所得 · 结算」，实际进入下一圈；章回重温也不发研究点。1.2 分别显示「进入第 N 圈」与重温的结算说明。
- 悟道页「当前配置变化」在平衡 4 下用基础 mods 起算（雷威显示 +15%→+40%）。1.2 改用引擎实际累加的 `traitMods`。
- 更换货架后旧的替换面板仍指向同一下标，会买入新货架同位置的物品（确认框显示的是实际物品）。1.2 换货架时清除替换状态。

以上战斗与秘境修复均属错误修复，对在途局同样生效，不消费或改变战斗随机抽样，不改其他数值、刷怪与经验。

### 构建、验收与依赖

- 浏览器验收脚本曾把 file URL 的 `.pathname` 当作文件路径，得到百分号编码路径，仓库位于含空格或中文的目录（以及 Windows）时截图与下载写入失败。1.2 统一改用普通路径；CI 改在检出目录 `qingzhu 青竹` 中运行完整流程，以后同类问题先在 CI 失败。
- 离线成品实际内嵌了 tailwindcss、tw-animate-css 的样式与复制进仓库的 shadcn/ui 组件，内嵌声明却只列 12 个 JS 包。1.2 的构建同时识别 Tailwind 编译进样式表的包与本地组件副本，内嵌声明增至 15 个包，THIRD_PARTY_NOTICES.md 与依赖清单 bundledInOffline 同步；`check:release` 逐项对照打包表、清单与两份 HTML 的内嵌声明。
- 隐私扫描补上本机仓库根、主目录、临时目录与用户名生成的路径形态（含 `/Volumes/…`、`-Volumes-…`、URL 编码与 Windows 盘符），范围扩大到两份 HTML 与玩家包文本；目前没有实际泄露。
- 源码白名单在有 `.git` 时与 `git ls-files` 比对，误放的未跟踪文件会让打包和检查失败。`check:release` 硬编码四个期望附件并核对根目录入口；`build:release` 开始时删除旧的 SHA256SUMS、manifest 与 github/ 副本，兼容版构建失败时保留原始错误并恢复默认资源。
- 视频介绍结尾页与口播稿不再写死版本号，`test:intro` 要求页面与口播稿中的版本号都等于当前游戏版本；补齐若干源码的 SPDX 版权头。
- 1.1 发布后为 CI 偶发问题改写的 B3 检查（按已保存字节重新打开页面，代替 `page.reload()`）一并收录，并补全失败诊断。
- 依赖安全：1.1 发布后新公布的公告使 `npm audit` 报 18 项（15 项高危、3 项严重）。1.2 升级 oxfmt 0.72.0（tinypool 2.2.0），sharp 以 overrides 固定 0.35.5，并更新 proxy-addr、source-map-js 与 MCP SDK 等间接依赖，共 6 项公告修复；离线成品内嵌的 15 个包版本不变。唯一剩余的 braces 公告（GHSA-vfj7-8cjw-p6xm）上游尚无修复版，仅经构建期工具处理项目自身的固定模式。CI 改用 `npm run audit:gate`：高危及以上一律失败，只放行登记在案且上游仍未修复的公告，修复版发布后门禁会重新失败。
